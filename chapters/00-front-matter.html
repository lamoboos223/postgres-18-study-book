Front matter

How this book works, and how the lab VMs must look

Do this once. Every later lab assumes these hostnames, IPs, and names. PostgreSQL is not installed here.

1. What you need to know

You are an experienced engineer, not a career DBA. This book teaches PostgreSQL administration: how a cluster is laid out, why WAL exists, how roles differ from SQL Server logins, and how to recover a database you actually care about.

The exam this book aims at is EDB Essentials for PostgreSQL v18 — community PostgreSQL 18, not EDB Postgres Advanced Server / Oracle-compatibility extras.

  • Chapters 1–2 are architecture. You can read them before the VMs are perfect.
  • The first PostgreSQL install is Chapter 3, on pg-primary only.
  • pg-standby stays unused until Chapter 15. Do not “helpfully” pre-build a replica.

3. Deep explanation

Why two VMs

Backup is a copy of data. Replication is a running second server that replays WAL. Those are different tools with different failure modes. The book keeps a second machine so Chapter 15 is not a thought experiment.

Why these names never change

Certification questions punish sloppy vocabulary. The book uses one set of nouns so “database vs schema” and “role vs OS user” stay distinct.

4. PostgreSQL 18 example

There is no psql yet. The “example” is making the VMs tell you who they are.

hostname
hostname -I
cat /etc/os-release
ip -4 addr show
hostname prints the kernel hostname. hostname -I lists IPv4/IPv6 addresses. /etc/os-release is the Debian version source of truth. ip -4 addr shows which NIC owns 192.168.56.10 or .11.

5. Production perspective

🏭 Production note. Real estates name hosts on purpose: pg-prod-a, not debian. DNS, TLS certs, and runbooks all assume a stable hostname. Changing it later is cheap on a lab VM and expensive in production.

6. Hands-on lab

On each Debian VM, set the name and a host-only IP that matches the book. Adjust the NIC name if yours is not enp0s8.

On the primary VM

sudo hostnamectl set-hostname pg-primary
echo '192.168.56.10 pg-primary
192.168.56.11 pg-standby' | sudo tee -a /etc/hosts
hostnamectl set-hostname writes the systemd hostname so it survives reboot. The /etc/hosts lines let the VMs resolve each other without DNS.

On the standby VM

sudo hostnamectl set-hostname pg-standby
echo '192.168.56.10 pg-primary
192.168.56.11 pg-standby' | sudo tee -a /etc/hosts

Give each VM a static address on the same host-only network your hypervisor already uses. If you already have 192.168.56.10 / .11, keep them and only fix hostnames.

⚠️ Destructive if you reuse a production NIC. Do not point a work laptop’s corporate interface at these IPs. Only change the host-only / internal adapter you created for this lab.

7. Lab verification

On pg-primary:

hostname
# expected: pg-primary

hostname -I
# must include 192.168.56.10

ping -c 2 192.168.56.11
# expected: replies from pg-standby

command -v psql || echo "psql not installed yet — correct for Chapter 00/01"

On pg-standby:

hostname
# expected: pg-standby

ping -c 2 192.168.56.10

From Windows (PowerShell), SSH should work:

ssh labhost@192.168.56.10
ssh labhost@192.168.56.11
If your sudo user is not named labhost, keep your real username. The book only uses labhost as a label. The hostnames and IPs are the part that must match.

8. Troubleshooting

Symptom

You can SSH to a VM, but ping 192.168.56.11 fails from the primary.

Possible causes

  • Standby is powered off or on a different virtual network.
  • Wrong NIC got the address (NAT vs host-only).
  • Hypervisor firewall / “host-only” adapter not installed on Windows.

Investigation

ip -4 addr
ping -c 2 192.168.56.11
ip route

Diagnosis

If 192.168.56.10 is missing, the primary is not on the lab network. If the address exists but ping fails, the packets are not reaching the other VM — hypervisor network, not PostgreSQL.

Fix

Attach both VMs to the same host-only/internal network and assign the book IPs there. Do not “fix” this by installing PostgreSQL.

Verification

Two-way ping between .10 and .11.

9. Exam focus

🔥 Exam focus. The exam will not ask your VM hostname. It will punish mixing these words: cluster, instance, database, schema, role, OS user. Front matter exists so those words stay stable.
  • This book installs community PostgreSQL 18 from PGDG in Chapter 3.
  • EDB Essentials for PostgreSQL ≠ EDB Postgres AI Database Essentials (that exam is Enterprise Postgres / Oracle-compatible).
  • Debian package layout (/etc/postgresql/18/main) is a packaging convention, not a PostgreSQL-on-every-OS law.
