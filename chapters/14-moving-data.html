Chapter 14 · EDB: Moving Data

COPY, dump data-only, and what FDW is for

Bulk load is COPY, not thousands of single-row INSERTs. Logical dump can be data-only. Foreign Data Wrappers exist; Essentials wants you to know the name, not build an enterprise mesh.

1. What you need to know

COPY table FROM/TO is the server-side bulk API. \copy is the psql client-side variant (reads a file on the client). pg_dump --data-only dumps DML without DDL.

2. Mental model

COPYserver file or program
\copyyour laptop/VM file
pg_dump --data-onlySQL or custom
▼ not the same
pg_basebackupwhole cluster bytes

3. Deep explanation

Server COPY FROM '/path' requires the file to be visible to the server OS user and superuser (or a granted COPY privilege / pg_read_server_files in modern versions — do not memorize every grant name; know that server-side COPY is privileged).

\copy streams through the client. That is what you use from a workstation.

FDW: CREATE EXTENSION postgres_fdw; then a foreign server — query another PostgreSQL as if it were a table. Essentials: “exists, used for moving/querying remote data,” not a full course.

4. PostgreSQL 18 example

\copy app.products TO '/tmp/products.csv' WITH (FORMAT csv, HEADER true);
\copy app.products FROM '/tmp/products.csv' WITH (FORMAT csv, HEADER true);
The second command would duplicate rows unless you truncated or used a staging table. Use a staging table in the lab.

5. Production perspective

🏭 Production note. Disable indexes or load into a staging table, then INSERT…SELECT, for huge loads. Watch WAL generation. COPY still writes WAL (unless you use unlogged tricks you should not use blindly).

6. Hands-on lab

sudo -u postgres psql -d study_lab

CREATE TABLE app.products_stage (LIKE app.products INCLUDING ALL);
\copy app.products TO '/tmp/products.csv' WITH (FORMAT csv, HEADER true)
\copy app.products_stage FROM '/tmp/products.csv' WITH (FORMAT csv, HEADER true)
SELECT count(*) FROM app.products_stage;

sudo -u postgres pg_dump -d study_lab -a -t app.users -f /tmp/users_data.sql
# -a data-only, -t table

7. Lab verification

head /tmp/products.csv
sudo -u postgres psql -d study_lab -c "SELECT count(*) FROM app.products_stage;"
wc -l /tmp/users_data.sql

8. Troubleshooting

Symptom

COPY ... FROM '/tmp/products.csv' → permission denied.

Diagnosis

You used server COPY. The server cannot read your file, or you are not allowed to. Use \copy instead.

9. Exam focus

🔥 Exam focus. COPY vs \copy. data-only dump vs schema dump vs base backup. FDW is a tool name, not a backup strategy.

10. One-minute revision

  • \copy CSV to staging.
  • pg_dump -a for data-only.
  • Do not confuse with physical backup.

Review questions

Q1. Why did server COPY fail when \copy worked?

Different process, different filesystem view, different privilege model. \copy is the client reading the file.
