Chapter 5 · EDB: Database Clusters

What lives inside PGDATA

A cluster is one data directory and one running server. This chapter walks the Debian 18/main tree so “base backup” and “tablespace” are not abstract later.

1. What you need to know

Official definition (again): a cluster is all databases managed by one instance, stored in one data directory. Debian: /var/lib/postgresql/18/main. Important children: base/ (per-database files), global/ (cluster catalogs, including roles), pg_wal/, pg_tblspc/, pg_stat/, control file.

2. Mental model

PGDATA = cluster
base/one folder per database OID
global/roles, pg_database, pg_control
pg_wal/WAL segments
pg_tblspc/links to tablespaces
config on Debian/etc/postgresql/18/main

3. Deep explanation

Each database has an OID. Files in base/<oid> are relations (tables, indexes) named by filenode, not by SQL name. That is why you do not back up a table by copying users from the filesystem.

pg_default is the default tablespace (base/). pg_global is cluster-wide catalogs. User tablespaces are directories elsewhere with a symlink in pg_tblspc.

A second cluster on the same VM = second initdb, second port, second memory budget. Debian: pg_createcluster 18 lab2 --port 5433. EDB’s extra cluster example uses initdb -D /edbstore and port = 5434.

Know these initdb flags: -D data dir, -E encoding, -U superuser name, -W password prompt, -X WAL directory, --wal-segsize, -k / checksums. If -D is omitted, PGDATA is used.

pg_ctl (Debian: pg_ctlcluster 18 main …): start, stop, restart, reload, status, promote, init. Stop modes: smart (wait for clients), fast (default, roll back), immediate (crash, recovery on start). Reload is also SELECT pg_reload_conf();.

sudo -u postgres /usr/lib/postgresql/18/bin/pg_controldata /var/lib/postgresql/18/main | head
pg_controldata prints cluster control info (system identifier, latest checkpoint). EDB module 5 exam bait.
⚠️ Destructive. pg_dropcluster 18 lab2 --stop deletes that cluster’s data. Never point it at main unless you mean to destroy the book lab.

4. PostgreSQL 18 example

sudo -u postgres psql -d postgres -c "SHOW data_directory;"
sudo -u postgres psql -d postgres -c "SHOW config_file;"
sudo ls /var/lib/postgresql/18/main
sudo ls /var/lib/postgresql/18/main/base
SHOW data_directory is the live PGDATA. ls base shows numeric database directories. postgres OS user owns these files (mode 700).
sudo -u postgres psql -d postgres -c "SELECT oid, datname FROM pg_database ORDER BY 1;"

5. Production perspective

🏭 Production note. Put PGDATA on its own volume. Do not use the mount-point directory itself as PGDATA (official initdb advice: create a subdirectory). Tablespaces are not a substitute for a real storage plan; they complicate backup.

8. Troubleshooting

Symptom

Permission denied listing PGDATA.

Fix

Use sudo ls or sudo -u postgres ls. Do not chmod 777 PGDATA.

9. Exam focus

🔥 Exam focus. Cluster = PGDATA. initdb initializes it. Multiple clusters = multiple instances. Tablespace ≠ database. File names in base/ are OIDs/filenodes.

10. One-minute revision

  • base/ databases, global/ cluster catalogs, pg_wal/ WAL.
  • Debian splits config to /etc/postgresql/18/main.
  • Second cluster = second port + second directory.

Review questions

Q1. Where are role definitions stored on disk?

Cluster catalogs under global/, not inside one database’s base/<oid> folder. That is why roles are cluster-wide.

Q2. What happens if you copy only base/ and skip pg_wal / global?

You do not have a consistent cluster. Use pg_basebackup or a documented filesystem backup with WAL, not ad-hoc copies.
