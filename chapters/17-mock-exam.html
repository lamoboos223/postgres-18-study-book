Appendix

Final mock exam

Cover the answers. This is practice in the style of Essentials thinking, not leaked EDB items.

Questions

1. A PostgreSQL cluster is:

  1. Two servers with automatic failover
  2. All databases of one instance in one data directory
  3. One schema named public
  4. The postgres database only

2. Default wal_level in PostgreSQL 18 is:

  1. minimal
  2. replica
  3. logical
  4. archive (as a distinct current value)

3. True / False. Changing io_method can be done with reload only.

4. After COMMIT (default synchronous_commit), which is guaranteed on disk?

  1. All dirty heap pages for the table
  2. WAL for that commit
  3. A checkpoint
  4. VACUUM of dead tuples

5. You granted SELECT on app.users but omitted schema USAGE. What happens?

6. Scenario. Remote connection refused; ss shows 127.0.0.1:5432 only. First fix?

7. Best tool for PITR:

  1. pg_dump only
  2. Base backup + WAL archive
  3. COPY TO
  4. EXPLAIN ANALYZE

8. What happens if a physical slot stays inactive for days?

9. VACUUM FULL vs VACUUM — one sentence each.

10. Scenario. Standby connected, replay_lsn lags sent_lsn. Name two things to inspect.

11. True / False. \c study_lab is the same mechanism as SQL Server USE.

12. Which file answers “may this host connect as this role to this database”?

Answer key

1 B. Official cluster definition. A is HA marketing.

2 B. Default is replica. archive is a legacy alias mapped to replica, not a separate modern setting you should choose.

3 False. io_method is set at server start (postmaster). Restart required.

4 B. WAL first. Heap pages may still be dirty.

5 Permission denied for schema app. USAGE is required to resolve names.

6 listen_addresses still localhost — change it and restart. Then check firewall / pg_hba if bind is correct but auth fails.

7 B. Dump is a logical snapshot, not PITR.

8 Primary keeps WAL for that slot → disk growth → eventual outage. Drop or repair the standby.

9 VACUUM reclaims dead tuples in place for reuse. VACUUM FULL rewrites the table, takes a heavy lock, can return space to the OS.

10 Standby apply (queries, conflicts, IO). Compare LSN columns in pg_stat_replication. Check hot standby conflicts / max_standby_streaming_delay.

11 False. \c opens a new connection to another database.

12 pg_hba.conf (then role/password, then GRANT).
