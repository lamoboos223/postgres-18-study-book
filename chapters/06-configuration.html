Chapter 6 · EDB: Configuration

postgresql.conf, pg_hba.conf, reload vs restart

If you cannot find a setting or you restart when a reload would do, you will drop sessions for no reason. This chapter also opens the host-only network so later labs can connect to 192.168.56.10.

1. What you need to know

Three files you must name on the exam:

FileDebian pathJob
postgresql.conf/etc/postgresql/18/main/postgresql.confGUC settings
pg_hba.confsame directorywho may connect how
pg_ident.confsame directoryOS user → role maps for ident/peer

Live values: pg_settings or SHOW. Context column tells you if a change needs reload or restart.

3. Deep explanation

pg_hba.conf is ordered. First match wins. Typical Debian local lines use peer. Remote lines need a host rule and listen_addresses not localhost only.

Password method for modern PostgreSQL is scram-sha-256, not md5 if you can avoid it.

ALTER SYSTEM SET ... writes postgresql.auto.conf and still needs reload/restart per parameter. Prefer editing the Debian file or ALTER SYSTEM — not both fighting each other blindly.

reload = SIGHUP: existing sessions keep running; they pick up reloadable GUCs on next check. restart = stop + start: connections drop.

4. PostgreSQL 18 example

sudo -u postgres psql -d postgres -c "SHOW config_file;"
sudo -u postgres psql -d postgres -c "SHOW hba_file;"
sudo -u postgres psql -d postgres -c "SELECT name, setting, context, pending_restart FROM pg_settings WHERE name IN ('listen_addresses','shared_buffers','wal_level','io_method','max_connections');"
context values such as postmaster mean restart. sighup means reload. pending_restart is true if you changed a restart-only GUC and have not restarted yet.

5. Production perspective

🏭 Production note. Change one thing, reload/restart, verify with SHOW. Do not open listen_addresses = '*' and 0.0.0.0/0 trust. Use a jump network and SCRAM. Track max_connections vs a pooler.

6. Hands-on lab

Allow the host-only subnet to reach PostgreSQL with SCRAM. Edit as root:

sudo grep -n "listen_addresses" /etc/postgresql/18/main/postgresql.conf

Set:

listen_addresses = '*'
For this lab, listen on all interfaces of the VM. The firewall/hypervisor still limits who can route to .10. In a tighter lab you could set 192.168.56.10 only.

Add above overly broad rejects, at the bottom of pg_hba.conf is fine if no later line overrides — first match wins, so put specific lab lines before reject if you add any:

host    study_lab    lab_admin    192.168.56.0/24    scram-sha-256
host    postgres     lab_admin    192.168.56.0/24    scram-sha-256

sudo pg_ctlcluster 18 main restart
# listen_addresses is a restart-level change
sudo pg_ctlcluster 18 main reload
# use reload for later pg_hba-only edits
pg_ctlcluster 18 main restart stops and starts cluster 18/main. Existing sessions die. reload sends SIGHUP and keeps sessions.

From Windows or from the VM:

psql -h 192.168.56.10 -U lab_admin -d study_lab
# password: lab_admin_lab_only

7. Lab verification

sudo -u postgres psql -d postgres -c "SHOW listen_addresses;"
sudo ss -lnt | grep 5432
# 0.0.0.0:5432 or *:5432

psql -h 127.0.0.1 -U lab_admin -d study_lab -c "SELECT current_user;"

8. Troubleshooting

Symptom

Service is up, remote psql says connection refused.

Possible causes

  • Still listening on localhost only (no restart after listen_addresses).
  • VM firewall (nft/ufw).
  • Wrong NIC / IP.

Investigation

sudo -u postgres psql -d postgres -c "SHOW listen_addresses;"
sudo ss -lntp | grep 5432
sudo -u postgres psql -d postgres -c "SELECT * FROM pg_hba_file_rules;"

Diagnosis

If ss shows only 127.0.0.1:5432, the server is not bound to the host-only IP. If it binds but auth fails, that is pg_hba / password, not “refused.”

Fix

Set listen_addresses, restart, then fix pg_hba and reload.

Verification

psql -h 192.168.56.10 -U lab_admin -d study_lab works.

9. Exam focus

🔥 Exam focus. First matching pg_hba line wins. Reload vs restart. pg_settings is the source of truth for the running value. pg_ident.conf is not pg_hba.conf.

10. One-minute revision

  • Three files: conf, hba, ident.
  • Reload when you can; restart when context says postmaster.
  • Lab: listen + SCRAM from 192.168.56.0/24 for lab_admin.

Review questions

Q1. You changed shared_buffers and ran reload. Nothing changed. Why?

shared_buffers is a postmaster / restart parameter. pending_restart will be true until restart.

Q2. True / False. A later pg_hba line can override an earlier match for the same connection.

False. First match wins. Order is the whole point.
