Chapter 7 · EDB: Data Dictionary

Catalogs, information_schema, and stats views

The dictionary is how a DBA answers “what exists?” without guessing. Three layers: pg_catalog (truth), information_schema (SQL-standard, narrower), pg_stat_* (activity, not structure).

1. What you need to know

Every database has pg_catalog. Cluster-wide facts (roles, databases, tablespaces) are visible from any connection via catalogs like pg_roles and pg_database. Per-database objects (tables in study_lab) appear when you are connected to that database.

3. Deep explanation

information_schema is for portable SQL. It hides a lot of PostgreSQL-only objects. Exam trap: a table exists in pg_class but not where a naive information_schema.tables filter looks.

Useful views (you will reuse these forever):

ViewUse it for
pg_databaseDatabases in the cluster
pg_roles / pg_authidRoles (passwords only on authid, superuser)
pg_namespaceSchemas
pg_classTables, indexes, sequences
pg_indexIndex definitions
pg_settingsGUCs
pg_stat_activitySessions
pg_stat_databasePer-database counters
pg_locksLock waits

4. PostgreSQL 18 example

sudo -u postgres psql -d study_lab

SELECT datname FROM pg_database ORDER BY 1;
SELECT nspname FROM pg_namespace ORDER BY 1;
SELECT relname, relkind FROM pg_class
WHERE relnamespace = 'public'::regnamespace
ORDER BY 1;
SELECT * FROM information_schema.tables WHERE table_schema = 'public';
SHOW search_path;
regnamespace casts a schema name to its OID for catalog joins. relkind r = ordinary table, i = index, S = sequence, v = view.

5. Production perspective

🏭 Production note. Monitoring products query pg_stat_*. Resetting stats (pg_stat_reset()) wipes counters — do not do that casually on prod. Catalog bloat is rare; user table bloat is common (Chapter 13).

6. Hands-on lab

sudo -u postgres psql -d study_lab -c "SELECT name, setting FROM pg_settings WHERE name LIKE 'wal%';"

8. Troubleshooting

Symptom

relation "users" does not exist but you swear you created it.

Investigation

SELECT current_database(), current_schemas(true);
SELECT n.nspname, c.relname
FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE c.relname = 'users';

Diagnosis

Wrong database, wrong search_path, or the table is in app (Chapter 8).

9. Exam focus

🔥 Exam focus. pg_catalog vs information_schema. Stats views are not the same as catalogs. \d reads catalogs.

10. One-minute revision

  • Catalogs = structure. Stats = activity. information_schema = portable subset.
  • Connect to the right database before describing its tables.

Review questions

Q1. Why can you see pg_roles from study_lab but not a table that lives only in another database?

Roles are cluster-wide catalogs. User tables belong to one database’s catalogs.
