Databases and roles

CREATE ROLE lab_admin LOGIN CREATEDB CREATEROLE PASSWORD '...';
CREATE DATABASE study_lab OWNER lab_admin;
CREATE SCHEMA app;
GRANT CONNECT ON DATABASE study_lab TO app_user;
GRANT USAGE ON SCHEMA app TO app_user;
GRANT SELECT ON ALL TABLES IN SCHEMA app TO app_user;

Backup and restore

pg_dump -d study_lab -Fc -f study_lab.dump
pg_restore -d study_lab_restore study_lab.dump
pg_dumpall -g          # roles only, common pattern
pg_basebackup -h 127.0.0.1 -D /path -Fp -Xs -P
SHOW summarize_wal;    # on for incremental
pg_basebackup -D /incr --incremental=/full/backup_manifest -Fp -Xs -P
pg_combinebackup /full /incr -o /combined
pg_verifybackup /full
# PITR: restore_command + recovery.signal in PGDATA (not standby.signal)

Maintenance

VACUUM (VERBOSE) app.orders;
ANALYZE app.orders;
REINDEX TABLE app.orders;
vacuumdb --all
-- VACUUM FULL / CLUSTER only when you accept the lock

Replication

CREATE ROLE replicator LOGIN REPLICATION PASSWORD '...';
SELECT pg_create_physical_replication_slot('standby1');
pg_basebackup -h 192.168.56.10 -U replicator -D ... -Fp -Xs -P -R --slot=standby1
SELECT pg_is_in_recovery();
-- promote (lab only, after fencing the old primary)
sudo pg_ctlcluster 18 main promote
# or: SELECT pg_promote();
-- logical (needs wal_level=logical)
CREATE PUBLICATION lab_pub FOR TABLE app.users;

Exam must-know (say these without the book)

  • Cluster vs database vs schema
  • Process per connection
  • WAL vs data files vs checkpoint
  • MVCC + VACUUM vs VACUUM FULL
  • Roles cluster-wide; GRANT per object
  • pg_hba first match; reload vs restart
  • pg_dump vs pg_basebackup; backup ≠ replica; recovery.signal vs standby.signal
  • Incremental: summarize_wal + pg_combinebackup + pg_verifybackup
  • Physical streaming, cascading, slots vs wal_keep_size, pub/sub, promote
  • COPY FREEZE; virtual generated columns; RLS
  • PG 18: io_method is not “skip WAL”
