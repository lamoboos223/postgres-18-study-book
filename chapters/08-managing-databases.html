Chapter 8 · EDB: Creating & Managing Databases

Schemas and the study_lab tables

Now the lab becomes an application: schemas app, ops, audit and tables users, products, orders.

1. What you need to know

A database is created from a template (default template1). A schema is a namespace inside one database. search_path decides unqualified names. public exists by default; this book prefers explicit app.

2. Mental model

study_lab
appusers products orders

3. Deep explanation

CREATE DATABASE newdb TEMPLATE template0 is the clean copy when template1 has leftover objects. You cannot drop a database you are connected to. Encoding/locale are fixed at create time (from template / initdb).

Constraints live in the table: PRIMARY KEY, FOREIGN KEY, CHECK, UNIQUE, NOT NULL.

4. PostgreSQL 18 example

sudo -u postgres psql -d study_lab

CREATE SCHEMA app;
CREATE SCHEMA ops;
CREATE SCHEMA audit;
SET search_path TO app, public;

CREATE TABLE app.users (
  id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  email      text NOT NULL UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE app.products (
  id    bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  sku   text NOT NULL UNIQUE,
  name  text NOT NULL,
  price numeric(12,2) NOT NULL CHECK (price >= 0)
);

CREATE TABLE app.orders (
  id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id    bigint NOT NULL REFERENCES app.users(id),
  status     text NOT NULL DEFAULT 'new',
  created_at timestamptz NOT NULL DEFAULT now()
);
GENERATED ... AS IDENTITY is the SQL-standard autoincrement (preferred over old serial in new work). timestamptz stores UTC instants.

5. Production perspective

🏭 Production note. One database per noisy tenant is a last resort (roles and WAL are still shared). Schemas are the usual isolation inside an app. Do not put app tables in template1.

6. Hands-on lab

Run the SQL above, then:

INSERT INTO app.users (email) VALUES ('ada@example.com'), ('al@example.com');
INSERT INTO app.products (sku, name, price) VALUES
  ('SKU-1', 'Notebook', 12.50),
  ('SKU-2', 'Cable', 4.00);
INSERT INTO app.orders (user_id, status) VALUES (1, 'paid');

CREATE TABLE ops.events (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  kind text NOT NULL,
  payload jsonb NOT NULL DEFAULT '{}'::jsonb,
  at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE audit.audit_logs (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  actor text NOT NULL,
  action text NOT NULL,
  at timestamptz NOT NULL DEFAULT now()
);

7. Lab verification

SELECT u.email, o.status
FROM app.orders o
JOIN app.users u ON u.id = o.user_id;

SELECT nspname FROM pg_namespace WHERE nspname IN ('app','ops','audit');

8. Troubleshooting

Symptom

ERROR: schema "app" does not exist

Fix

Connected to postgres instead of study_lab, or the CREATE SCHEMA failed. \c study_lab and \dn.

9. Exam focus

🔥 Exam focus. Database vs schema vs table. search_path. CREATE DATABASE ... TEMPLATE. You cannot drop the database you are in.

10. One-minute revision

Review questions

Q1. What happens if you CREATE TABLE users (...) with search_path still public?

You get public.users, not app.users. Qualify names in this book: app.users.
