Chapter 1 · EDB: Introduction and Architectural Overview

What PostgreSQL actually is

If you treat PostgreSQL like “SQL Server, but Linux,” you will fail both the exam and production. This chapter locks the vocabulary: server, cluster, database, schema, role, and the process-per-connection model.

1. What you need to know

PostgreSQL is a client/server, object-relational database. The server program is named postgres. Clients (psql, JDBC, your API) speak the PostgreSQL protocol. One running server manages one database cluster: a single data directory containing every database, plus cluster-wide objects such as roles and WAL.

Official PostgreSQL 18 wording (Architectural Fundamentals): a session is a client plus a server process. The supervisor postgres process accepts connections and forks a new process per connection. After that, the client talks only to its backend. The supervisor stays up, waiting for the next connection.

PostgreSQL 18 note. The process-per-connection model is still the default architecture in 18. Do not study older “Postgres is getting a thread-per-connection rewrite” rumors as exam facts. Internals such as asynchronous I/O appear in Chapter 2; they do not replace this connection model.

3. Deep explanation

What is a cluster?

Official docs: a database cluster is a collection of databases managed by a single running server instance. The SQL standard calls this a catalog cluster. On disk it is one data directory (PGDATA). initdb creates it. After initdb, the cluster contains:

  • postgres — default database for tools and humans. The server does not require it, but many utilities assume it exists.
  • template1 — default source for CREATE DATABASE.
  • template0 — pristine template. Use it when template1 is dirty or you need a clean encoding/locale copy.

Do not put application tables in template0 or template1.

Why PostgreSQL isolates databases so hard

A client connection is always to exactly one database. There is no USE otherdb that switches catalogs the way SQL Server does. Cross-database queries are not normal SQL; you need dblink, a foreign data wrapper, or a second connection. That is a feature: catalogs, search_path, and permissions stay scoped.

Roles (users) are cluster-wide. Creating app_user once makes that role visible to every database. Privileges on tables are per-database objects. This split is the #1 SQL Server confusion.

Why a process per connection?

PostgreSQL chose OS processes, not a giant threaded server, for crash isolation and a simpler memory model. The cost is RAM per connection and the need for a pooler (PgBouncer, etc.) when an app opens hundreds of connections. Essentials exam: you must be able to say “one backend process per connection” and know that idle connections still occupy a process.

Where Chapter 2 will go next

Shared buffers, WAL, checkpoints, background workers, MVCC — those are inside this cluster. This chapter only places the boxes. If you cannot draw cluster → database → schema, stop and redraw it.

4. PostgreSQL 18 example

You should not have psql yet. These are the commands you will run after Chapter 3. Read them now so the vocabulary is not new later.

psql -d postgres -c '\conninfo'
psql -d postgres -c '\l'
psql is the official client. -d postgres selects the database (not the cluster). \conninfo shows host, port, user, database for this session. \l lists databases in the cluster. 
psql -d postgres -c "SELECT datname FROM pg_database ORDER BY 1;"
psql -d postgres -c "SELECT current_database(), inet_server_addr(), inet_server_port();"
pg_database is a cluster catalog: it lists every database. current_database() is this session only. inet_server_addr() / inet_server_port() show where this backend is listening from the server’s point of view — useful later when you debug “which host did I actually hit?”

If someone already installed PostgreSQL on your VM, you may peek. Do not create study_lab yet — that is Chapter 4.

5. Production perspective

🏭 Production note. One cluster per host is the usual story. A second cluster on the same VM means a second port, a second data directory, a second memory budget, and twice the backup surface. Apps should not open a raw connection per HTTP request; that pattern exhausts max_connections and RAM.
  • Scalability: add connections only through a pool. Scale read traffic with replicas (Chapter 15), not with “one database per microservice on the same cluster” unless you meant to share roles and WAL.
  • Reliability: a crash of one backend should not take down the supervisor. A crash of the machine takes down every database in that cluster together.
  • Security: cluster-wide roles mean a compromised superuser is a cluster event, not a single-database event.
  • Failure mode: filling the data-directory disk freezes the whole cluster — all databases, not just study_lab.

8. Troubleshooting

Symptom

You expected a clean lab, but ss -lnt shows 5432 already open.

Possible causes

  • A previous PostgreSQL install on this VM.
  • Another product bound to 5432.
  • You are on the wrong VM.

Investigation

hostname
sudo ss -lntp | grep 5432
ps aux | grep -E '[p]ostgres|[p]ostmaster'
dpkg -l 'postgresql*' 2>/dev/null | grep ^ii

Diagnosis

If dpkg shows postgresql-18, this VM is ahead of the book. That is not fatal — skip the install bits of Chapter 3 and use the inspection labs. If the version is 15/16/17, do not pretend it is 18.

Fix

Prefer a clean VM for the install chapter. If you keep the existing 18 cluster, treat it as 18/main and stay honest about what you did not install yourself.

Verification

psql --version
# must say 18.x if you are going to follow PostgreSQL 18 notes

9. Exam focus

🔥 Exam focus. Memorize the official definition: a cluster is all databases managed by one server instance, stored in one data directory. Know that template0/template1/postgres appear after initdb. Know process-per-connection.
  • The server executable is postgres. People still say “postmaster” for the supervisor — Chapter 2 will use both.
  • Connecting to postgres the database is not the same as becoming the postgres role, and neither is the OS user — three different things can share the name.
  • Trap: “cluster” in Kubernetes/Patroni marketing vs PostgreSQL’s data-directory cluster. On this exam, cluster means PGDATA unless the question is clearly about HA.
Remember. Cluster = one data directory + one running server. Database = a named catalog inside that cluster. Schema = a namespace inside one database.

10. One-minute revision

  • Client/server. Server program: postgres.
  • Supervisor forks one backend per connection.
  • Cluster = PGDATA = all databases + roles + WAL.
  • initdb creates postgres, template1, template0.
  • One connection → one database. Roles are cluster-wide.
  • SQL Server USE does not exist here.

Review questions

Q1. Multiple choice. A PostgreSQL database cluster is:

  1. Two or more servers doing automatic failover
  2. A collection of databases managed by one server instance, in one data directory
  3. A single schema that contains all tables
  4. The postgres database only

Answer: B. That is the official definition. A is HA marketing. C is a schema. D is one database inside the cluster.

Q2. True / False. After you connect, you can USE study_lab to switch databases the way SQL Server does.

False. You reconnect (or open another session) to the other database. psql has \c study_lab, which is a new connection, not a catalog switch inside one backend.

Q3. What happens if… two applications connect at the same time to the same cluster?

The supervisor forks two backend processes. They share the cluster’s memory and files; they do not share a single SQL session. Locks and MVCC (Chapter 2 / 11) coordinate their data changes.

Q4. Scenario. A developer says “we created a new cluster” and they mean they ran CREATE DATABASE billing. What do you tell them?

They created a database, not a cluster. A new cluster would be a new initdb / new data directory / new server instance (and usually a new port).

Q5. Multiple choice. Which objects are created by initdb and should not hold application tables?

  1. study_lab only
  2. template0 and template1
  3. pg_wal and pg_xlog
  4. Every schema named public

Answer: B. Official guidance: templates are not for actual work. pg_xlog is the pre-v10 WAL directory name — not an initdb database. public is a schema, not a template database.
