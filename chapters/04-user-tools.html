Chapter 4 · EDB: User Tools — Command Line Interfaces

psql, helpers, and the first lab roles

psql is the exam’s client. GUIs exist (pgAdmin). This chapter makes you fast on the CLI and creates lab_admin plus empty study_lab.

1. What you need to know

psql is an interactive terminal. Backslash commands are client meta-commands; they are not SQL. SQL ends with ;. Meta-commands start with \.

Also know: pg_isready, pg_lsclusters, pg_ctlcluster, createdb/createuser (thin wrappers around SQL).

3. Deep explanation

Connection string pieces: host, port, database, user. Local Debian default: Unix socket, port 5432, peer auth for the matching OS user.

CommandMeaning
\lList databases
\c study_labReconnect to that database (new session)
\dnList schemas
\dtList tables
\duList roles
\xExpanded display
\timingShow client elapsed time
\qQuit
\?Help for meta-commands
\h VACUUMSQL help

createuser and createdb are convenience binaries. In this book we mostly use SQL so you see the real privileges. EDB also lists dropuser / dropdb and the client env vars PGHOST, PGPORT, PGUSER, PGDATABASE (Chapter 3).

5. Production perspective

🏭 Production note. Prefer a personal superuser-equivalent only on jump hosts, not on laptops pointed at prod. Use ~/.pgpass (mode 0600) or a secret manager — never commit passwords. psql -v ON_ERROR_STOP=1 -f script.sql is how you run change scripts safely.

6. Hands-on lab

sudo -u postgres psql -d postgres

Inside psql:

CREATE ROLE lab_admin LOGIN CREATEDB CREATEROLE PASSWORD 'lab_admin_lab_only';
CREATE DATABASE study_lab OWNER lab_admin;
\l
\du
\c study_lab
SELECT current_user, current_database();
\q
LOGIN makes a role that can connect (a “user”). CREATEDB / CREATEROLE are DBA-practice flags, not superuser. CREATE DATABASE copies template1 by default. OWNER lab_admin makes lab_admin own the database.

Connect as the new role (password auth may still be local-only; if peer fails, use sudo -u postgres psql and SET ROLE for now — Chapter 6 fixes pg_hba):

sudo -u postgres psql -d study_lab -c "SET ROLE lab_admin; SELECT current_user;"

7. Lab verification

sudo -u postgres psql -d postgres -c "\l study_lab"
sudo -u postgres psql -d postgres -c "SELECT rolname, rolsuper, rolcreatedb, rolcreaterole FROM pg_roles WHERE rolname IN ('postgres','lab_admin');"

Expect study_lab listed, lab_admin not superuser, rolcreatedb and rolcreaterole true.

8. Troubleshooting

Symptom

psql: error: connection refused or Peer authentication failed.

Possible causes

  • Service down.
  • Wrong user: labhost is not a database role yet.
  • Peer requires OS name = role name.

Investigation

pg_isready
pg_lsclusters
sudo -u postgres psql -d postgres -c '\conninfo'

Fix

Use sudo -u postgres psql until Chapter 6 adds password/host rules. Do not create a superuser named after your login unless you intend to.

9. Exam focus

🔥 Exam focus. \c reconnects. \d describes objects. Role vs login: in PostgreSQL a role with LOGIN is what people call a user. psql is not the server.

Review questions

Q1. \l fails with a syntax error if you type \l; as SQL in some contexts — why is \l not sent to the server as SQL?

It is a psql meta-command. The client expands it (to a catalog query) or handles it locally.

Q2. True / False. CREATE ROLE lab_admin LOGIN is cluster-wide, not only for study_lab.

True. Roles live in the cluster. Ownership/grants are per object.
